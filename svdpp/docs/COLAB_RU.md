# Пошаговое обучение SVD++ в Google Colab

## Что потребуется

Файл `svdpp/SVDpp_MovieLens1M_Colab.ipynb` из общего GitHub-репозитория
и аккаунт Google. Исходники и полный MovieLens 1M скачиваются автоматически.

## 1. Получить ноутбук

Скачайте ноутбук из папки `svdpp/` репозитория
https://github.com/polushkin-ayu/ai360-recsys-2026.
Локальная установка Python для запуска в Colab не нужна.

## 2. Открыть готовый ноутбук

Откройте https://colab.research.google.com/.
Выберите «Файл → Загрузить блокнот» / «File → Upload notebook» и укажите
`SVDpp_MovieLens1M_Colab.ipynb`.
Если используется окно «Открыть блокнот», перейдите на вкладку «Загрузить».
При необходимости сохраните копию блокнота на Google Drive.

## 3. Включить GPU

«Среда выполнения → Сменить среду выполнения» / «Runtime → Change runtime type».
В поле аппаратного ускорителя выберите доступный GPU, например T4, если он
предлагается, и сохраните настройки. Нажмите «Подключиться» / «Connect».
Конкретная GPU и доступность бесплатных ресурсов зависят от Colab.

## 4. Подключить Drive

Запустите первую кодовую ячейку ноутбука кнопкой ▶ или `Shift+Enter`.
Она вызывает `drive.mount()`; выберите аккаунт и разрешите подключение.
В «Мой диск» создастся папка `SVDpp_MovieLens1M`.

## 5. Получить исходники

Запустите вторую кодовую ячейку. Она клонирует общий GitHub-репозиторий
в `/content/ai360-recsys-2026`; проект находится в его папке `svdpp/`.
Копия исходников сохраняется на Drive в `ai360_recsys_source.zip`.
После перезапуска Colab используется эта же копия, чтобы продолжение
проверяло те же исходники. Для нового опыта с обновлённым кодом задайте
другое имя `ZIP_PATH` в первой ячейке.

## 6. Выполнить подготовительные ячейки

По очереди запустите ячейки разделов 3–6:

1. Связать папки результатов и checkpoint с Drive.
2. Установить зависимости из `requirements.txt`.
3. Проверить PyTorch и CUDA. Должно быть `CUDA: True` и название GPU.
4. Скачать и подготовить данные, затем выполнить `audit`: 700 146 train и 150 002 validation.

Ячейка подготовки сама скачает MovieLens 1M и проверит контрольные суммы.
Не устанавливайте в Colab CPU-версию PyTorch вместо установленной GPU-версии.

## 7. Задать параметры

В ячейке раздела 7 по умолчанию:

```python
K = 20
LR = 0.003
REG = 1.0
EPOCHS = 100
SEED = 11
RUN_NAME = "k20_lr0003_reg1_seed11"
```

`K` — размер эмбеддингов. `LR` — learning rate Adam.
`REG` — lambda в `MSE + lambda/N * L2`, где N — число train-оценок.
`EPOCHS` — максимальное общее число эпох. Это пример настроек первого запуска;
полный подбор ещё не выполнен. `RUN_NAME` задаёт папку опыта.

Чтобы повторить ваш прежний запуск, используйте:

```python
K = 2
LR = 0.001
REG = 0.01
EPOCHS = 100
SEED = 11
RUN_NAME = "k2_lr0001_reg001_seed11"
```

После изменений выполните ячейку заново, чтобы пересоздать команду.

## 8. Запустить обучение

Выполните ячейку раздела 8. Она запускает:

```bash
python -u train.py --k 20 --lr 0.003 --reg 1 --epochs 100 --seed 11 --device cuda --output results/single/k20_lr0003_reg1_seed11
```

Фактическая команда строится из параметров предыдущей ячейки.
В консоли будут строки с `epoch`, `train`, `val`, `best`, `sec`.
`train` и `val` — RMSE, `best` — лучшая validation RMSE.
Лог показывается на первой эпохе, затем раз в 10 эпох и при завершении.
Контрольная точка сохраняется после каждой эпохи.
Модель остановится при достижении лимита или после 40 эпох без улучшения validation.

## 9. Посмотреть и скачать результат

Раздел 9 покажет метрики и график RMSE по эпохам. Раздел 10 скачает ZIP результата.
На Google Drive файлы находятся в
`SVDpp_MovieLens1M/results/single/<RUN_NAME>/`:

| Файл | Для чего нужен |
|---|---|
| `model.pt` | Веса лучшей модели по validation |
| `last.pt` | Продолжение обучения с состоянием Adam |
| `history.csv` | Train/validation RMSE по эпохам |
| `metrics.json` | Метрики лучшей эпохи и окружение |
| `learning_curve.png` | Train/validation RMSE по эпохам |
| `train_loss.png` | Train loss и MSE по эпохам |
| `run_config.json` | Настройки опыта |

Эта команда не вычисляет test RMSE. Validation выбирает лучшую эпоху;
test нужен для окончательной оценки после всех решений о параметрах.

## 10. Продолжить после прерывания

Откройте тот же блокнот, подключите GPU, повторите подготовительные ячейки.
Сохраните прежние `K`, `LR`, `REG`, `SEED` и `RUN_NAME`.
Выполните ячейку настройки и ячейку обучения. В логе появится `resume epoch ...`.
Обучение возобновится из `last.pt` на Drive. Незавершённая эпоха будет выполнена заново.

`EPOCHS=100` означает довести опыт до 100-й эпохи, включая уже сохранённые,
а не добавить ещё 100. Для увеличения бюджета поменяйте только `EPOCHS`.
Если уже сработал early stopping, увеличение лимита не отменяет его.
Изменение `k`, `lr`, `reg`, seed, batch или patience требует нового `RUN_NAME`.
Смена CPU/GPU может дать небольшие численные отличия при продолжении.

## 11. Получить график RMSE от k

Один запуск рисует RMSE **от эпохи**. График RMSE **от k** требует нескольких
моделей и подбора `lr`/`lambda` отдельно для каждого `k`.
Полный протокол описан в README и последнем текстовом разделе ноутбука:
`tune → diagnose → fit → diagnose → freeze → test → plot`.
Текущая сетка в `configs/svdpp-ml1m.json` использует два этапа:
144 предварительных запуска по 100 эпох на seed 11, затем подтверждение лучшей
lambda для каждого lr на трёх seeds — 108 подтверждений до 500 эпох, минимум 100.
В 36 подтверждениях seed 11 продолжается из checkpoint предварительного этапа.
После подбора выполняются 90 финальных повторов. Это длительный эксперимент.

Команда `tune` выполняет оба этапа и умеет продолжать прерванные запуски.
`candidates_per_learning_rate` регулирует число lambda, оставляемых для каждого lr.
Для полного перебора задайте `tuning_strategy: {"mode": "grid"}` в копии config
с новыми output/checkpoint-папками. Test в отборе не используется.

Обычный одиночный запуск рассчитан на продолжение после перезапуска Colab.
Полный исходный протокол фиксирует всё окружение: при смене GPU, PyTorch
или ОС он может потребовать новую серию с новыми output/checkpoint-папками.
Завершённые полные опыты повторно используются только при совпадении fingerprint.

## Графики подбора и финальной серии

В полном эксперименте `tune` автоматически сохраняет в `tuning_plots/`
отдельную тепловую карту предварительного этапа `screening_heatmap_k<k>.png`
с рамками оставленных пар, тепловые карты подтверждённого среднего validation RMSE
по lr/lambda, сводку лучших кандидатов по k
и кривые обучения лучшей пары по tuning seed. Перерисовать сохранённые
результаты без обучения можно командой:

```python
!python -u experiment.py plot-tuning --device cuda
```

После `fit` каждый финальный запуск получает отдельный график
`final_curves/<run_id>_loss.png`; `final_loss_curves.png` показывает все
финальные seed по k. Loss — `MSE + lambda/N * L2` на train после эпохи.
MSE показана отдельно на графиках отдельных запусков.

После `freeze` и `plot` доступна validation-кривая RMSE от k.
После `test` повторите `plot`, чтобы добавить test-кривую.
Среднее и sample SD считаются по пяти финальным seed.

## Быстрый режим на одном seed

После подготовки проекта можно выполнить вместо длительной серии:

```python
!python -u fast.py --seed 11 --minutes 55 --device cuda
```

Он проверяет всю сетку k и пар lr/lambda, но ограничивает эпохи и время,
а выбранные модели использует для test без независимых финальных повторов.
Результаты: `results/svdpp-ml1m-fast/seed11/`. Папка быстрого режима должна
быть связана с Drive, если требуется сохранение после разрыва сессии.
Подробный протокол и ограничения: `docs/FAST_RU.md`.
