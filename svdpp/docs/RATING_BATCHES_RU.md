# SVD++ с батчами по оценкам для сравнения с FM

Текущая серия: 13 значений k, seed 11, не более 25 эпох.
Команда из папки проекта:

```powershell
.\.venv\Scripts\python.exe -u train_ratings.py --config configs/svdpp-ml1m-ratings-active.json --output results/svdpp-ml1m-ratings-active/seed11 --seed 11 --device cpu
```

Полный train MovieLens 1M: 700146 оценок. Перед каждой эпохой заново
перемешиваются все оценки. Батч — 1024 оценки, последний — 754;
за эпоху выполняется 684 отдельных обновления Adam, как у FM.
Накопление градиентов и объединение обновлений не используются.

Активная сетка k: 1,2,3,4,5,10,20,30,40,50,100,150,200.
Отложены k=6,7,8,9,15. Исходная полная сетка из 18 значений
остаётся в configs/svdpp-ml1m-ratings.json для отдельного будущего запуска.
Настройки фиксированы: learning_rate=0.001, reg_bias=0.01,
reg_factors=10, init_std=0.01, максимум 25 эпох, patience=10.
Регуляризация делится на число оценок train. Проверка validation
выполняется после каждой эпохи; восстанавливается лучшая эпоха.

Формула SVD++ сохраняется: mu + bu + bi + qi @ (pu + sum(yj)/sqrt(history_size)).
Истории содержат только фильмы train. Параметры P,Q,Y независимы.
Кешируется только неизменная разреженная матрица истории H и её транспонированная
матрица. H @ Y вычисляется заново на каждом шаге; градиент по Y равен H.T @ grad
с соответствующей нормировкой. Это та же сумма и тот же градиент,
что embedding_bag; тест сравнивает прогнозы, градиенты и обновления Adam.
Средняя оценка mu остаётся фиксированной средней train.

Результаты находятся отдельно от быстрых опытов:
results/svdpp-ml1m-ratings-active/seed11/.
В runs/k<K>/ находятся history.csv, progress.json, last.pt, model.pt,
metrics.json и learning_and_loss.png. В history.csv записано число
обновлений за эпоху и накопленное число шагов Adam. last.pt сохраняется
после каждой эпохи вместе с состоянием Adam, генератором перестановок
и лучшей моделью. Повторение той же команды продолжает незавершённую
модель и переиспользует завершённые. Код, данные и настройки должны совпадать.

После каждой завершённой модели обновляются metrics_summary.csv,
rmse_vs_k.png/pdf, rmse_vs_k_log.png и final_loss_curves.png.
До завершения всей сетки сводный график содержит только validation.
Затем модели и выбор k фиксируются в frozen.json и вычисляется test;
test-кривая добавляется на итоговый график. Настройки не выбираются по test.
Один seed не позволяет оценить разброс между инициализациями.

Время не ограничено. Early stopping и лимит 25 эпох сохраняются;
достижение лимита отдельно отмечается в метриках.
