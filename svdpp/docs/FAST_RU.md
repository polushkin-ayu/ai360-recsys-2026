# Быстрая серия SVD++ на одном seed

Цель — пройти всю сетку k за один запуск с бюджетом 55 минут на CPU ноутбука.
Время проверяется между эпохами, поэтому возможен небольшой выход за бюджет;
оставлен запас до часа. До реального запуска длительность не подтверждена.
Это отдельный короткий эксперимент: он не гарантирует сходимость или качество
длительной серии до 500 эпох. Если бюджет исчерпан до завершения всех k,
`fast_status.json` содержит `complete=false`, test не открывается.

## Запуск

Из папки проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe fast.py --plan
.\.venv\Scripts\python.exe fast.py --seed 11 --minutes 55 --device cpu
```

Первая команда только показывает объём работы; она не обучает модель и не
читает датасет. Вторая запускает весь процесс: подбор, фиксацию моделей,
оценку test и графики. Здесь она не выполнялась.

Параметры находятся в `configs/svdpp-ml1m-fast.json`. Для двух других seeds
используйте `--seed 22` или `--seed 33`; папки создаются отдельно для каждого seed.
В Colab после обычной подготовки проекта:

```python
!python -u fast.py --seed 11 --minutes 55 --device cuda
```

## Что ускорено

- Все 18 значений k и все 8 пар lr/lambda сохранены.
- Все 700 146 train-оценок участвуют в каждой завершённой эпохе; подвыборок нет.
- Предварительный этап: до 8 эпох на каждую пару, один seed.
- Для каждого learning rate сохраняется лучшая lambda. Обе пары продолжаются
  до 30 эпох; learning rate 0.003 обязательно получает место в подтверждении.
- Максимум 1 944 прохода по train, обычно меньше благодаря остановке и времени.
- В батче 512 пользователей; состав групп и индексы строк готовятся заранее,
  а порядок групп перемешивается каждую эпоху. Не нужны повторные torch.unique.
- Кешируются только индексы train-историй. Суммы обучаемых y_j вычисляются заново
  при каждом обновлении, поэтому формула SVD++ и градиенты сохраняются.
- Train loss и validation RMSE оцениваются на первой, каждой пятой и последней
  эпохе. На графиках показаны фактические номера этих эпох, без интерполяции метрик.
- ID и целевые оценки проверяются один раз на всю серию.
- Выбранная модель каждого k используется для test без нового финального обучения.
  В этом режиме нет независимых финальных повторов или стандартного отклонения.

Оставшееся время распределяется между кандидатами с учётом k. Часть бюджета
зарезервирована для test и графиков. Ограничение времени имеет приоритет над
минимальным числом эпох; такие модели получают `time_limited=true`.
Если даже минимальная работа не помещается, серия остаётся незавершённой.
Короткий отбор может исключить lambda, которая была бы лучше после долгого обучения.

## Результаты

Папка: `results/svdpp-ml1m-fast/seed11/` (или seed22/seed33).

- `fast_status.json`: все ли k завершены, фактическое время, попадание в час,
  число выбранных моделей, ограниченных временем. `converged=false` означает,
  что сходимость этим коротким экспериментом не установлена.
- `metrics_summary.csv`: validation/test RMSE каждого k на одном seed.
- `rmse_vs_k.png`: validation и test RMSE от k, без выдуманных error bars.
- `final_loss_curves.png`: train loss выбранных моделей по эпохам.
- `tuning_plots/`: отдельные карты предварительного отбора и подтверждения.
- `frozen.json`: выбранные параметры и модели, зафиксированные до доступа к test.

Повтор той же команды использует завершённые результаты. Незавершённая серия
может быть продолжена из checkpoint; новый вызов даёт новый временной бюджет,
поэтому суммарное время нескольких вызовов может превысить час.
Изменение кода/config/окружения требует новых папок результатов и checkpoint,
как в обычном эксперименте. Длительный протокол остаётся доступен через
`experiment.py` и `configs/svdpp-ml1m.json`.

## Проверка вычислительной стоимости

На Celeron N5095 прямой проход всех train-батчей занял примерно 0,042 секунды
при k=2, 0,260 при k=50 и 0,904 при k=200. Замер выполнен на случайных весах
без градиентов и оптимизатора. Измеренная часть всей быстрой серии составляет
около 9 минут. Градиенты, Adam, подготовка и сохранение добавят время;
фактическая длительность полного обучения пока не проверена.
Числа и метод: `FAST_RUNTIME_ESTIMATE.json`.

## Продолжение запусков, остановленных по времени

Если первая серия завершилась, но в `fast_status.json` есть
`selected_models_time_limited > 0`, можно продолжить все остановленные по времени
запуски, включая предварительный этап и подтверждение:

```powershell
.\.venv\Scripts\python.exe -u complete_fast.py --device cpu
```

Команда по умолчанию читает `results/svdpp-ml1m-fast/seed11/`. Для другого seed
передайте `--source results/svdpp-ml1m-fast/seed22`. Исходные результаты и
контрольные точки остаются без изменений. Новые сохраняются в
`results/svdpp-ml1m-fast-completed/seed11/` и
`artifacts/svdpp-ml1m-fast-completed/seed11/`.

Продолжение загружает последние веса, Adam и RNG, а не начинает обучение
заново с лучшей validation-эпохи. Временного ограничения нет. Сохраняются
исходные пределы 8/30 эпох, patience=10 и список кандидатов первого запуска.
Все случаи без `time_limited=true` переиспользуются без обучения. Некоторые
запуски одновременно достигли ранней остановки и временного лимита; для них
дополнительные эпохи не требуются. Финальные веса выбираются по обновлённому
validation RMSE среди исходных кандидатов, затем заново оценивается test и
строятся графики. Независимого финального обучения в этом режиме нет.

`completion_status.json` содержит число завершённых случаев, дополнительные
эпохи и оставшиеся случаи с ограничением времени. Повтор той же команды
продолжает незавершённые контрольные точки и пропускает готовые случаи.
Сходимость не гарантируется: предел 30 эпох и один seed сохранены. Общая
длительность первой серии и продолжения может превысить час.
