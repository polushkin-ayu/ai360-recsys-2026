# Общий план работы

Распределение ответственности и проверяемые утверждения: [координация работы](coordination.md).

## Цель

Изучить FM второго порядка и проверить, улучшают ли факторизованные взаимодействия user/item предсказание рейтингов относительно bias-модели на небольшом срезе MovieLens 100K. При готовности основного сравнения — исследовать добавление жанров.

Основная статья — **Factorization Machines — Factorized Polynomial Regression Models**, введение — Rendle 2010. FM — основной проект группы. Отдельного исследования на синтетике не проводим; маленькие искусственные примеры нужны только для проверки реализации.

## Этапы и требуемые результаты

| Этап | Работа | Результат |
|---|---|---|
| Понять метод | Факторизация попарных коэффициентов, связь с MF, обучение, k и регуляризация | Собственная схема и формула; каждый объясняет модель и гипотезу |
| Подготовить данные | Воспроизводимый небольшой срез MovieLens, общий split, обработка ID | Описание выборки, размеры, покрытие известных ID, проверенная команда подготовки |
| Проверить реализацию | Bias-модель и FM второго порядка, forward и градиенты | Проверки корректности и повторяемый маленький запуск |
| Провести сравнение | Bias → FM user/item, один протокол | RMSE, кривые обучения, время и параметры; повторения по seed |
| Дополнить при готовности | Жанры, небольшой анализ k/регуляризации | Абляция на том же split с ясными ограничениями |
| Защитить исследование | Вопрос → метод → эксперимент → вывод | Концепт к mid-review; реальные результаты и собственный постер к финалу |

FM user/item эквивалентна MF с bias. На одном срезе не делаем универсальных выводов. Подробности — [протокол](research_plan.md).

## Роли

Для шести участников: 2 — данные и оценка; 2 — модели и проверки; 2 — обучение, эксперименты и анализ. При пяти последний блок ведёт один участник с поддержкой коллег. Если DCN занимаются двое и на FM остаются четверо, две пары объединяют задачи моделей и данных/экспериментов, дополнительные исследования сокращаем.

До кодирования согласуем формат признаков/target, ID строк и split, интерфейс predict, конфигурации и таблицу результатов. Проверки перекрёстные, метод и защиту понимают все; отдельной роли только для слайдов нет. Имена назначаем на занятии.

## DCN — необязательное направление

1–2 человека после общей DL-справки могут разобрать cross-слой и, если успеют, сравнить DNN/DCN на общем срезе MovieLens. Можно оставить только теорию или отказаться совсем. DCN не блокирует mid-review и не является обязательным результатом финала. На итогах сегодняшнего дня и во вторник оцениваем загрузку: при проблемах обязательного FM участники помогают основному проекту.
