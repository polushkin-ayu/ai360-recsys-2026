# ТЗ команде 1 — данные и оценка

**Основная задача:** [Issue #1](https://github.com/polushkin-ayu/ai360-recsys-2026/issues/1). **Проверки:** К5–К6.

## Цель и границы

Подготовить единый воспроизводимый срез MovieLens 100K, разбиение и функцию RMSE для bias и FM. На первом этапе нужны только user/item ID и рейтинг. Жанры — после основного сравнения. Реализация bias и FM принадлежит команде 2; сравнительные запуски — команде 3.

## Входы и договорённости

Источник: https://grouplens.org/datasets/movielens/100k/ . До кодирования согласуйте с командами 2 и 3 формат таблиц/массивов, пути загрузки и порядок предсказаний. Исходное наблюдение получает устойчивый row_id.

Передаваемые поля: user_idx, item_idx, rating, row_id. Дополнительно: n_users, n_items, словари исходных ID и описание split. Индексы пользователей и фильмов — отдельные пространства; для общего FM признаки фильма можно смещать на n_users. Плотную one-hot-матрицу создавать не требуется.

## Работы

1. Загрузить данные; записать источник и checksum. Проверить число оценок, пользователей/фильмов, пропуски, диапазон рейтингов, повторяющиеся пары user/item и распределение числа оценок. Сохранить краткий отчёт, без большого EDA.
2. С фиксированным seed выбрать набор пользователей и все их оценки. Ориентир — 10–20 тысяч оценок, размер уточнить по скорости пилота. Зафиксировать правило, число пользователей и фактический размер. Не выбирать срез по значениям рейтинга или качеству модели.
3. Создать одно случайное разбиение примерно 70/15/15. Проверить непересечение row_id. Если есть повторные наблюдения одной пары user/item, согласовать их обработку до разбиения: одна пара не должна попадать в разные части.
4. Построить словари ID только по train. Из основной оценки validation/test исключить строки с неизвестным пользователем или фильмом; сохранить размеры до/после и покрытие. Это эксперимент на известных ID, не оценка холодного старта.
5. Передать всем одинаковые разбиения и формат входов. Проверить, что списки оцениваемых row_id совпадают у моделей.
6. Реализовать общую RMSE: для y=[1,3], prediction=[2,1] результат sqrt(2.5). Проверить порядок строк, размерности и конечность значений. Не допускать неявного broadcasting массивов разных форм.
7. Добавить проверенную команду получения/подготовки в data/README.md. Сырые и подготовленные данные не коммитить; код, конфигурация и инструкция хранятся в Git.

## Критерии приёмки и передача

- Другой участник одной документированной процедурой получает тот же срез и split.
- К5–К6 подтверждены отчётом/проверками; покрытие известных ID указано.
- Команда 2 получает входы и размеры; команда 3 — те же входы, метрику и описание выборки.
- В Git есть код подготовки, конфигурация и инструкция; результат не требует устных пояснений автора.

## Организация и сдача

Назначьте в основном Issue одного ответственного и проверяющего из другой команды. Имена пока не назначены. Фиксируйте ID проверки, commit, команду запуска, конфигурацию/seed, фактический результат и ограничения. Незавершённую проверку не отмечайте выполненной; приложите воспроизводимый блокер и следующий шаг.

Временные интервалы — ориентир сегодняшнего плана; при сдвиге начала сохраняйте порядок и общий показ в конце дня. Полная реализация к mid-review 7 октября не обязательна. Код пишут студенты.
