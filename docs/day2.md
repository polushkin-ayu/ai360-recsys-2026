## Общий блок обучения

Пример для всех — рейтинг, скалярный выход и MSE. Прослеживаем полный цикл: признаки → параметры/векторы → предсказание → loss → градиенты по цепному правилу → шаг оптимизатора → следующий batch. На двух нейронах показываем, как градиенты складываются для общего входа; все градиенты шага считаются при текущих параметрах, затем параметры обновляются. Кратко отличаем train от validation. Sigmoid/logloss нужны лишь как контекст CTR-статьи DCN.

## После обеда: конкретные первые действия

- Модели: прямой и быстрый forward FM на одних параметрах; затем проверка градиентов и обучение на маленьком представимом наборе.
- Обучение и анализ: общий цикл обучения и журнал; одна конфигурация для пилота, графики train loss и validation RMSE.
- MovieLens/оценка: подготовка данных и разбиения, проверка неизвестных ID, RMSE на ручном примере, bias-baseline.

Каждая часть согласует входы с остальными до кодирования. При запуске DCN её участники сначала проходят общую основу и убеждаются, что обязательные роли FM покрыты. Самостоятельный разбор DCN не забирает обязательное время общей защиты.

Тождество для Т2 (сумма по f — по координатам факторных векторов):

```text
Σ_{i<j} ⟨v_i, v_j⟩ x_i x_j
= 1/2 · Σ_f [ (Σ_i v_if x_i)² − Σ_i v_if² x_i² ].
```

Квадраты справа сокращают самовзаимодействия при раскрытии скобок; это не добавление членов xᵢ² в модель.

В соответствующем Issue или PR указываем ID утверждения и доказательство проверки. Один PR может закрывать несколько пунктов, но чекбокс отмечаем только после предъявления результата. Для Г1–Г3 «проверено» не означает «получен выигрыш».

```text

Статус: запланировано / в работе / проверено / заблокировано
Исполнитель: <логин>
Доказательство: <вывод/схема или commit + команда + конфигурация/seed>
Ожидаемый критерий: <равенство с допуском / отсутствие пересечений / сравнение метрик>
Фактический результат: <значения и ссылка на файл; заполнить после проверки>
Вывод и ограничения: <что установили и чего эта проверка не доказывает>
Следующий шаг: <действие и срок>
```

Для экспериментов дополнительно заполняем [журнал](experiment_log.md). Пример связи: К5 → #1 → сохранённые ID split и отчёт покрытия; К1 → #2 → проверка равенства; Г1 → #3 → таблица метрик на моделях из #2 и данных из #1.
