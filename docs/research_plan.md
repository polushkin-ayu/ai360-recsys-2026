# План исследования FM на MovieLens

**Обновление 6 октября 2026:** по решению команды основной источник заменён на полный MovieLens 1M. Случайный split 70/15/15, seed 42, train-only mappings и известные ID остаются обязательными. [Точные правила, размеры и общий split ID](movielens1m-data.md). Упоминания среза MovieLens 100K ниже описывают прежний этап; новые модели используют `data/processed/movielens1m`.


## Вопрос и объём

Как добавление факторизованных взаимодействий user/item к bias-модели влияет на качество предсказания рейтинга на небольшом срезе MovieLens? Дополнительный вопрос, если успеваем: помогают ли жанры фильма?

Основная статья — Factorization Machines — Factorized Polynomial Regression Models; Rendle 2010 — введение. Обязательна FM второго порядка. Высшие порядки, SVD++, большие переборы и отдельное синтетическое исследование исключены из основного объёма. [Этапы и результаты](work_plan.md).

Формула: ŷ = w₀ + Σᵢ wᵢxᵢ + Σᵢ<ⱼ ⟨vᵢ,vⱼ⟩xᵢxⱼ. Самовзаимодействий xᵢ² в этой сумме нет. При двух активных признаках user/item FM совпадает с матричной факторизацией с bias; не выдаём их за два разных класса моделей.

## Данные и небольшой срез

Источник — [MovieLens 100K](https://grouplens.org/datasets/movielens/100k/). Предсказываем оценку, не клик. Сам набор уже небольшой: для отладки берём срез, а переход ко всем 100K оценкам — только после рабочего пилота и при достаточном времени.

Стартовый ориентир для среза — 10–20 тысяч оценок, окончательный размер выбираем по скорости пилота. Воспроизводимо выбираем фиксированный набор пользователей с seed и сохраняем их оценки; фактический размер записываем. Не выбираем пользователей или фильмы по величине рейтинга и не меняем срез ради лучшей метрики. Ограничение на активность, если понадобится, фиксируем заранее и описываем смещение выборки.

Фиксируем источник, checksum, seed выборки, ID строк, число оценок/пользователей/фильмов и распределение рейтингов. Один и тот же срез используется всеми моделями.

Для пилота — случайное разбиение примерно 70/15/15 на train/validation/test с фиксированным seed. Словари и преобразования строим по train. Основную оценку считаем на известных пользователях и фильмах: строки validation/test с неизвестным ID исключаем из этой метрики, но обязательно сообщаем их количество и долю сохранённых строк. Не подбираем фильтры по тестовым рейтингам. Такой эксперимент не оценивает холодный старт и не является временным прогнозом.

## Обязательные сравнения

1. Bias: общий уровень + bias пользователя + bias фильма.
2. FM второго порядка по user/item ID.

Разница показывает эффект добавления взаимодействий в этой постановке. Проверяем гипотезу улучшения validation/test RMSE, но не обещаем выигрыш. Отдельная модель глобального среднего полезна как быстрая проверка pipeline.

Если обязательное сравнение готово, добавляем жанры: сравниваем FM с жанрами и без них при одном split. Для более строгого анализа добавляем линейные эффекты жанров к bias-модели: иначе нельзя приписать весь эффект именно новым взаимодействиям. Кодирование multi-hot жанров и нормировку фиксируем заранее.

## Обучение и оценка

Обучаем по MSE с регуляризацией, основная метрика — RMSE. Подбор k, регуляризации и остановки — только по validation, с небольшим заранее согласованным бюджетом. Начинаем с одной рабочей конфигурации; после неё — несколько значений k/регуляризации. Test используем после выбора настроек. Правило clipping, если применяется, одинаково для моделей и фиксируется заранее.

Сохраняем train loss и validation RMSE по эпохам, таблицу итоговых метрик, число параметров, время и оборудование. До финала повторяем главное сравнение минимум с тремя seed инициализации на фиксированном split, показываем значения и разброс. Это устойчивость к обучению, а не к выбору среза; повторение разбиений — дополнительное исследование.

## Проверки корректности

- Прямое и быстрое вычисление FM совпадают при одинаковых параметрах.
- Градиенты проверены конечными разностями или независимым autograd на маленьком примере.
- FM по user/item совпадает с MF с bias при одинаковых параметрах.
- Маленький заведомо представимый пример обучается; это техническая проверка, не синтетический эксперимент для научных выводов.
- Разбиения не пересекаются по ID наблюдений; неизвестные ID и покрытие метрики учтены.
- RMSE проверена на ручном примере; предсказания и loss конечны.

## Необязательный DCN на 1–2 человека

Только если покрыты основные задачи FM. Можно ограничиться теорией или полностью отказаться. При реализации используем исходную DCN 2017, общий срез, признаки, split и RMSE. Выход скалярный без sigmoid, обучение MSE — адаптация CTR-архитектуры к рейтингу.

Внутреннее сравнение — DNN/DCN при одинаковых embeddings и deep-ветке. Проверяем формулу cross-слоя, размерности и градиенты; сообщаем число параметров и время. DCN не является условием готовности защиты.

## Границы выводов

Один небольшой срез не доказывает универсальное превосходство FM, эффективность на холодном старте или причинный механизм обобщения. Без контролируемой синтетики не заявляем, что установили, при какой истинной структуре коэффициентов факторизация выигрывает. Это проверка идей статьи на рейтингах MovieLens, не воспроизведение Netflix. Отрицательный результат допустим при корректном протоколе.
