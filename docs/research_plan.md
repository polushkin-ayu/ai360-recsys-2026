# План исследования

## Вопрос и гипотеза

Общий вопрос: как разные способы моделирования взаимодействий признаков влияют на качество и сложность модели?

Направление FM: как факторизация коэффициентов помогает обобщать на новые сочетания? Направление DCN: что даёт добавление cross-ветки к небольшой DNN?

Гипотеза: совместное использование параметров улучшает обобщение на новые сочетания известных категорий при небольшом объёме данных, если выбранная размерность факторов достаточно хорошо описывает истинные взаимодействия. Малое число факторов может также ограничить качество. Преимущество заранее не гарантируется.

## Основной материал и объём

Основная статья — Factorization Machines — Factorized Polynomial Regression Models (Freudenthaler, Schmidt-Thieme, Rendle). Оригинальная FM 2010 — введение. Две тройки работают над FM второго порядка и исходной DCN 2017 после общего блока по DL. Высшие порядки FM и SVD++ остаются дополнительными. FM пока основная статья для постера; роль DCN уточняется к mid-review. Классический ML допустим, предварительное знание DL не требуется.

Исследуем линейные эффекты и попарные взаимодействия без повторов индекса: сумма a_ij*x_i*x_j по i<j. В FM a_ij заменяется скалярным произведением v_i и v_j. Это не произвольная полная полиномиальная регрессия со всеми квадратами: самовзаимодействия x_i² исключены из этой формулы.

## Эксперимент 1 — контролируемая синтетика

Небольшое число категориальных полей с one-hot-кодированием. Команда реализует генератор, задающий линейные эффекты, взаимодействия и шум. Сохраняются параметры генератора и seed.

Модели: регуляризованная линейная регрессия; линейная регрессия с явными независимыми попарными взаимодействиями; FM второго порядка. Входные признаки и целевая переменная одинаковы. Размер пространства ограничить так, чтобы явные взаимодействия помещались в память.

Основная ось — объём обучающих данных. Validation/test фиксированы для одной реализации генератора, train-подвыборки вложенные и не пересекаются с ними. Во всех train-подвыборках проверяем наличие категорий из оцениваемого набора. Отдельно отмечаем пары категорий, которые не встречались совместно в train. Новую полную комбинацию нескольких полей не выдаём автоматически за новую попарную комбинацию. Холодный старт не смешиваем с обобщением на новые пары.

Два сценария:

1. Истинные попарные коэффициенты получены из небольших общих векторов — структура соответствует предположению FM.
2. Независимые коэффициенты на активных межполевых парах — контроль границ при том же выбранном небольшом k. Не предполагаем заранее, что FM обязательно проиграет.

Сценарий 1 благоприятствует FM по конструкции; явно указываем это. Масштаб сигнала и шума между сценариями контролируем. Главный график — RMSE от объёма train. До mid-review достаточно плана двух сценариев и маленького проверенного примера; полные кривые строим после него.

## Общий реальный датасет — MovieLens 100K

Источник: https://grouplens.org/datasets/movielens/100k/ . Предсказываем численную оценку фильма, не клик.

Модели направления FM:

1. Bias-модель: общий уровень + bias пользователя + bias фильма.
2. FM второго порядка с user ID и item ID.

FM с этими двумя активными ID совпадает по формуле с матричной факторизацией с bias. Не представляем их как разные классы моделей. Проверку равенства предсказаний выполняем при одинаковых параметрах.

Дополнительно: FM с жанрами и изучение влияния размерности k. Добавляем после готовности обязательных моделей.

Фиксируем checksum исходных файлов, размер и распределение оценок, кодирование ID, версию split и seed. Для эксперимента на известных пользователях/объектах проверяем их наличие в train; правило обработки и число исключённых неизвестных ID записываем. Не подбираем фильтры по тестовым оценкам. Временной прогноз — отдельная постановка; случайный split не называем временным.

## Направление DCN

Изучаем исходную DCN 2017 (v1), не DCNv2. На общем MovieLens предсказываем рейтинг: скалярный выход без sigmoid и обучение по MSE. Это адаптация архитектуры к регрессии, не воспроизведение исходного CTR-эксперимента.

Главное сравнение — небольшая DNN и DCN с той же deep-веткой и той же схемой embeddings. Сначала один cross-слой и проверенный запуск; затем, если хватает времени, 1/2/3 слоя. Число полных параметров при добавлении ветки меняется, поэтому такое сравнение не называем равным по числу параметров.

Проверки: формула x_next = x0 * (w_lᵀ x_l) + b_l + x_l, размерности и broadcasting, конечные градиенты, обучение на маленьком представимом примере. Показываем число параметров с embeddings и без них и время на указанном оборудовании.

## Общая работа двух подкоманд

Один основной датасет, target и train/validation/test; одна реализация RMSE. До практики согласуем исходные поля (user ID, item ID; жанры — по совместному решению). Одинаковая информация доступна обеим подкомандам; кодирование может отличаться. Дополнительные поля сравниваем как отдельную абляцию и явно обозначаем.

Подготовку данных и оценку делают совместно представители обеих троек, используя общий код. Модели используют согласованные входы, ID строк и единый формат предсказаний. Сравнение FM и DCN возможно, но не заменяет внутренних сравнений: bias/FM и DNN/DCN. По одному отличию RMSE нельзя приписать эффект конкретной архитектурной идее.

## Общий протокол

Основная метрика — RMSE; обучать можно по MSE с регуляризацией. Все модели внутри сравнения используют один split. Предобработка обучается только на train. Регуляризацию, k и правила остановки выбираем по validation с сопоставимым бюджетом. Test используем после выбора настроек. Правило clipping оценок, если оно применяется, фиксируем заранее и одинаково для сравниваемых моделей.

Показываем число параметров и время обучения с оборудованием. До финала повторяем главные сравнения минимум на трёх seed, разделяя seed генерации/разбиения и инициализации. Сохраняем индивидуальные результаты, среднее и разброс. Не делаем вывод об устойчивости по одному запуску.

## Проверки реализации

- Прямой перебор пар и быстрое вычисление FM дают одинаковые предсказания.
- Градиенты проверены на маленьком примере конечными разностями или независимым autograd.
- При нулевых взаимодействиях FM совпадает с линейной частью.
- FM по user/item ID совпадает с MF с bias при одинаковых параметрах.
- Train, validation и test не пересекаются по выбранным идентификаторам наблюдений; протокол новых пар проверен отдельно.
- Loss конечен и модель способна выучить небольшой заведомо представимый пример.

## Границы выводов

Это проверка идей статьи на синтетике и MovieLens, не численное воспроизведение результатов Netflix. Низкая ошибка train не доказывает обобщение. FM не гарантирует правильного предсказания новой пары и не решает автоматически холодный старт. Увеличение k не гарантирует улучшения.
